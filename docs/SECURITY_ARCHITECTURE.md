# Архитектура защищённых аккаунтов и модерации

Текущее состояние: GitHub Pages — статический сайт. Регистрации и серверных привилегий в нём нет. **Нельзя запускать публичную регистрацию с правами редактора, хранящимися в JS/localStorage**.

## Предлагаемая архитектура
- Frontend: текущий сайт, позднее отдельный домен и серверный backend (или Supabase Auth + PostgreSQL RLS + Edge Functions). Выбранный провайдер должен поддерживать rate limiting, аудит и MFA.
- Пользователи: email verification, защищённые сессии в HttpOnly Secure SameSite cookie на серверном варианте, контроль попыток входа и восстановление паролей.
- Хранение паролей: только провайдер авторизации / Argon2id на сервере, никогда plaintext.
- Роли: `student`, `editor`, `owner` **в приватной базе на сервере**. Роль не выводится в публичном профиле; отсутствие публичного бейджа не означает невидимость администратора для системных журналов.
- **Никакого общего «суперпароля».** Каждому владельцу — отдельный аккаунт + MFA/WebAuthn. Назначение `owner` — только существующим владельцем через серверный защищённый процесс с аудитом.
- По умолчанию запрет на изменения для всех; каждый write-эндпоинт проверяет авторизованного пользователя, роль и тип операции. Скрытые кнопки не обеспечивают безопасность.
- Учебный контент и субтитры хранятся с sourceVideoId, sourceType, reviewStatus и version. Владелец может публиковать/править/архивировать. Удаление — soft delete с журналом; важно сохранять историю учебных ответов.
- Видео YouTube показываются через embed, а не копируются. Аудиофайлы из архива используются только при подтверждённом праве на размещение.

## Схема данных
users: id, public_nickname, created_at
private_roles: user_id, role, granted_by, granted_at
lessons: id, video_id, playlist_id, source, status, version
phrases: id, lesson_id, pl, ru, source, reviewed_by, revision, status
attempts: id, user_id, lesson_id, phrase_revision, correct, created_at
mastery: user_id, lesson_id, phrase_revision, perfect_streak, last_at
plans: user_id, title, goal_minutes, goal_lessons, updated_at
tasks: id, user_id, title, done
admin_audit: id, actor_id, action, entity_id, before, after, created_at

## Политики
- student: SELECT только опубликованного контента, CRUD только своих планов/результатов; не может создавать или править уроки, фразы, ролики.
- editor: операции с контентом через серверные функции, ограниченные ролью; без управления владельцами.
- owner: управление контентом/модерацией и назначением редакторов; выдачу owner требует отдельного подтверждения другого владельца или защищённой процедуры восстановления.
- Никнеймы: нормализация Unicode (NFKC), длина 3–24, запрет управляющих/невидимых символов и смешения Unicode-алфавитов, список запрещённых слов с проверкой обходов (пробелы, цифры, похожие буквы). Публичный ник отдельно от email, не использовать для входа.
- Параметризованные SQL, серверная валидация, CSP, защита XSS, CSRF для cookie-сессий, проверка размеров и типов данных, ограничение загрузок, контроль MIME и сканирование вложений.
- Rate limit по IP и аккаунту; 2FA владельцам; уведомления о подозрительных действиях; бэкапы и мониторинг.
- Таблицы лидеров: добровольное участие, псевдонимы, антинакрутка (серверные задания/оценки и лимиты), без публикации email или списка администраторов.
- Персональные данные: удалить аккаунт и экспортировать прогресс, минимизация хранения, политика конфиденциальности; проверить применимое право до запуска регистрации.

## Критическое
Без настоящего backend, таблиц, миграций, ключей сервиса и настройки Auth никакие реальная регистрация, приватные роли и общая таблица лидеров не могут считаться внедрёнными. Эта документация — требования для следующего этапа, не имитация защищённой системы.
