# Учебная программа Polski wsłuch

## Маршрут ученика

Открой `academy.html`: **Категория → плейлист (или «Вне плейлистов») → видео → чтение / аудирование → тренажёр**. Кнопка «Далее → Тренажёр» активна сразу. Категория — тематический агрегатор и может включать несколько плейлистов; это не тождественные понятия. Определение категории выполняется по названию и данным плейлистов; неоднозначные уроки остаются в «Другие материалы». Категория C3 отображается только как дополнительная авторская, поскольку CEFR заканчивается C2.

Содержимое берётся из `data/videos.json` (плейлисты, видео, названия, описания, адреса донатов). Полные тексты — отдельно из `data/transcripts.json`, упражнения из `data/phrases.json`. Ни краткая фраза, ни пересказ не обозначаются как полная стенограмма.

Состояние видео (`pv-academy-v1`) и освоение тренажёров (`pv-learning-v1`) хранятся локально, без обязательной регистрации. Заполнение карточек и достижения вычисляются по `mastery[videoId].complete`, которое выставляется **после двух безошибочных раундов**, не только после просмотра. Процент просмотра использует YouTube IFrame Player API и считает время **фактического воспроизведения** (быстрая перемотка не засчитывается); при заблокированном YouTube API счётчик может оставаться на нуле. Ученик всегда может продолжить без достижения 90%. Видео без готовых фраз не имеют полноценного видео-специфичного теста — требуется поступление контента из разрешённого источника.

Достижения создаются по алгоритму: первое освоение, 5/10/25/50/100 уроков, каждое полностью освоенное непустое содержание плейлиста и категории. Никакой ложной статистики и фиктивных результатов.

## Подключение YouTube API

1. В Google Cloud Console создай проект и включи **YouTube Data API v3**, ограничь ключ разрешённым API и, по возможности, использованием для серверных запросов.
2. Открой GitHub репозиторий → **Settings → Secrets and variables → Actions → New repository secret**.
3. Добавь секрет с точным именем `YOUTUBE_API_KEY`. **Никогда не вставляй ключ в HTML, JavaScript, CSS, JSON или git-коммиты**.
4. Открой Actions → workflow `sync-youtube.yml` → **Run workflow**. По расписанию он также синхронизирует метаданные.
5. Проверь `data/videos.json`: `source` должен стать `youtube-data-api`; новые плейлисты и полные списки видео должны появиться. Если API недоступен, имеющийся сборщик использует RSS с ограниченным охватом последних публикаций.

**Важно:** обычный YouTube Data API API-key обеспечивает доступ к публичным метаданным, но не даёт универсального скачивания полных текстов/субтитров. Для субтитров владельца канала нужны соответствующие права OAuth, экспорт SRT/VTT самим владельцем либо иной разрешённый источник. Также API не обеспечивает извлечение оригинальной аудиодорожки произвольного видео — аудиотека использует собственный разрешённый архив, а учебные фразы могут озвучиваться TTS.

## Архитектура

Текущий этап — статический сайт с единым JSON-источником данных и несколькими страницами. Категории, видео и достижения рассчитываются на клиенте; GitHub Actions выступает защищённым процессом загрузки метаданных. Не следует внедрять React, Java или C# лишь ради редизайна; при дальнейшем расширении разумный вариант — единый React/TypeScript интерфейс с компонентами видеоплеера, чтения, упражнений и профиля, с сохранением тех же JSON-контрактов и без утраты гостевого режима.

## Контроль качества

Проверить вручную: категории, плейлисты и «Вне плейлистов», поиск урока, YouTube playback на ПК/телефоне, переключение текст/аудио, ссылки на Boosty, прямой переход в тренажёр с правильным видео, обновление прогресса после двух раундов, достижения, настройки темы, мобильное меню. Публикация GitHub Pages и воспроизведение реального YouTube видео должны быть проверены в браузере после merge.
