# Проверка безопасности «Польский вслух» — 13.10.2026

## Область проверки
Публичный репозиторий `Danvanmih/polskiy-vsluh`, ветка `master`, статические HTML/JavaScript/CSS, внешние подключения, сценарий импорта пользовательских презентаций, локальный профиль и GitHub Actions. Проверка выявляет **известные риски в исходниках**, но не доказывает отсутствие уязвимостей.

**Не проведено:** независимый пентест, MITM/сетевой мониторинг реальных посетителей, проверка внутренних систем VK, полный анализ старых экспортированных HTML-игр по 8–8,5 МБ, автоматическое подтверждение статуса сайта в репутационных базах. Попытка открыть опубликованный GitHub Pages через веб-инструмент завершилась ошибкой; этот факт не означает блокировку или недоступность сайта для других.

## Результаты (статический аудит)
1. **Высокий риск — PDF.js 3.11.174.** Публичный загрузчик использовал `pdfjsLib.getDocument({data: ...})` без отключения выполнения eval, что соответствует известному классу уязвимости CVE-2024-4367 / GHSA-wgrm-67xf-hhpq. Исправлено `isEvalSupported:false` при извлечении текста. Это рекомендованная производителем временная защита, **не замена перехода на поддерживаемую версию PDF.js**.
2. **Средний риск — внешние библиотеки.** `learn.html` загружает JSZip 3.10.1 с jsDelivr и устаревшую PDF.js с cdnjs без Subresource Integrity. Компрометация стороннего ресурса или поставщика может затронуть страницу. Рекомендуется закрепить проверенные версии и подключить SRI или размещать проверенные копии на своём домене; PDF.js — обновить.
3. **Средний риск — обработка неподтверждённых файлов.** Ограничение размера исходного файла есть (16 МБ), но не было ограничения на число страниц PDF / слайдов PPTX и количество декодируемого текста. Добавлены отдельные верхние границы обработки PDF/PPTX. Полная защита от ZIP-бомб/злоумышленных файлов и OCR-материалов требует дополнительных нагрузочных тестов.
4. **Низкий риск, но значимо для доверия — кнопка «Войти».** На исходных страницах текст кнопки предполагал настоящую авторизацию, а `inline-profile.js` хранит только локальный никнейм, без серверной сессии. Статическая надпись изменена на «Локальный профиль»; опубликовано описание обработки данных.
5. **Низкий риск — thumbnail HTML.** В `audio-youtube-catalog.js` произвольный `v.thumbnail` из каталога вставлялся в HTML-атрибут `src` без экранирования. Данные текущего каталога содержат ссылки на YouTube, но при будущей компрометации источника могло возникнуть внедрение HTML. Исправлено: URL обложки формируется только из предварительно проверенного 11-символьного YouTube ID.
6. **Хорошие признаки:** не найдено запроса пароля VK в формах основных пяти страниц, локальный профиль не отправляет пароли или коды в сеть, импорты PPTX/PDF/TXT обрабатываются браузером и сохраняются в localStorage, ключ YouTube API используется скриптом GitHub Actions из `secrets.YOUTUBE_API_KEY` (не из фронтенда), ссылки на основное видео идут на YouTube.
7. **Отдельные области для анализа:** три сохранённых HTML-экспорта Scratch/ONAS (по ~8–8,5 МБ каждый), устаревшие страницы `new 1.html`/`new 2.html` и т. д.; наличие сторонних CDN и внешних ссылок требует проверки репутации. Нельзя из аудита основной страницы делать вывод о всём репозитории.

## Может ли это объяснять блокировку VK?
Не доказано. VK может ограничивать внешние ссылки по своей антифишинговой политике, а меры в отношении аккаунта могут иметь и другую причину. **Нужны точная URL, текст предупреждения и действия перед блокировкой**. Для проверки статуса — Google Safe Browsing Transparency Report, GitHub Pages, официальная поддержка VK. Не просить пользователя обходить предупреждение, если оно присутствует.

## Рекомендации владельцу
1. Сначала подтвердить у VK причину блокировки; приложить точную ссылку `https://danvanmih.github.io/polskiy-vsluh/`, скриншот предупреждения и объяснение, что это учебный каталог, а профиль локальный.
2. Перейти на поддерживаемую PDF.js ≥ 4.2.67, протестировать импорт/worker и закрепить проверенные зависимости (SRI или собственный хостинг).
3. Рассмотреть строгую CSP и запрет встраивания сайта во фреймы через HTTP-заголовки хостинга (в GitHub Pages нельзя полностью управлять headers, возможно понадобится другой хостинг/CDN).
4. Проверить старые опубликованные экспорты (включая игру) на сторонние запросы и при необходимости убрать лишние публичные копии **после согласования**.
5. Не добавлять настоящую авторизацию, платежи и права администратора без backend, MFA, защищённых серверных сессий и rate limiting.
